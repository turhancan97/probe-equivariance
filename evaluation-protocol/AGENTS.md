# AGENTS.md

Read this file first for any work inside `evaluation-protocol/`.

## Project Overview

`evaluation-protocol/` is the evaluation and probing layer for this repository. It trains regression probes on frozen vision backbones using image sequences generated by `unreal-motion-capture/`.

This subtree owns:

- dataset loading and target construction for the Unreal motion-capture layout
- frozen backbone feature extraction via `timm`
- per-group probe training for equivariance evaluation
- prediction visualization and smoke tests
- local documentation for how this subtree works

This file does not try to document the rest of the repository in detail. For broader repo context, inspect the top-level project files directly.

## Current Status

The current `evaluation-protocol/` surface supports:

- training regression probes with `train_equivariance.py`
- visualizing saved predictions with `visualize_equivariance.py`
- line targets as 1D normalized position values
- orbit targets as 2D `[cos(theta), sin(theta)]` values
- pooled backbone features with `pool: mean` and `pool: cls`
- patch-token features with `pool: patch`
- the standard MLP regression head in `configs/probe/regressor.yaml`
- the Efficient Probing head in `configs/probe/efficient_probing.yaml`

Recent validated state:

- the Efficient Probing path is implemented and has been reported as passing in the local `dinov3` environment
- visualization supports both pooled-feature probes and Efficient Probing checkpoints
- `README.md` documents installation, training, visualization, pooling modes, and Efficient Probing
- smoke tests exist in `tests/test_smoke.py`

## Key Architecture And Decisions

- Training is done per `(environment, mode, object)` group.
- The backbone is frozen. Only the probe head is trained.
- `pool: mean` and `pool: cls` use the cached-feature workflow.
- `pool: patch` is reserved for Efficient Probing and uses token-aware streaming over per-group dataloaders instead of caching all patch tokens in RAM.
- `pool: patch` excludes prefix tokens such as CLS before returning patch tokens.
- Efficient Probing currently supports `num_heads: 1` only.
- Visualization overlays train, valid, and test predictions on the same plot, with one ground-truth color and split-specific prediction colors.

Important constraints:

- `backbone.pool=patch` requires `probe=efficient_probing`
- non-Efficient-Probing probes should not be paired with `pool: patch`
- CLIP ViT backbones generally need `dataset.image_size=224`
- checkpoint saving must be enabled during training if visualization is needed later

## Canonical Commands

Preferred environment:

- use the local `dinov3` conda environment when available

Common commands:

```bash
cd evaluation-protocol
conda run -n dinov3 python train_equivariance.py
conda run -n dinov3 python visualize_equivariance.py result_dir=results/equivariance_my_run
conda run -n dinov3 python -m unittest discover -s tests -p 'test_smoke.py'
```

Common overrides:

```bash
conda run -n dinov3 python train_equivariance.py \
  experiment_name=my_run \
  dataset.root=/path/to/dataset \
  dataset.image_size=224 \
  training.save_checkpoints=true

conda run -n dinov3 python train_equivariance.py backbone.pool=cls

conda run -n dinov3 python train_equivariance.py \
  backbone.pool=patch \
  probe=efficient_probing
```
