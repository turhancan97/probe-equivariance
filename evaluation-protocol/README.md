# evaluation-protocol

## Introduction

`evaluation-protocol` is the evaluation side of this repository. It takes images generated by `unreal-motion-capture`, extracts frozen visual features with a pretrained backbone from `timm`, and trains small regression probes to measure how well those features preserve controlled camera/object transformations.

The current pipeline supports four motion modes from the Unreal dataset:

- `camera_line`
- `camera_orbit`
- `object_line`
- `object_orbit`

Targets are derived from the saved motion metadata:

- line modes predict a 1D normalized position along the line motion
- orbit modes predict a 2D angle encoding `[cos(theta), sin(theta)]`

Training is done per `(environment, mode, object)` group, and results are written to CSV files under `results/equivariance_<experiment_name>/`.

## Installation

### Option 1: use the existing `dinov3` environment

If you already have the `dinov3` conda environment on this machine, you can run everything through it:

```bash
conda run -n dinov3 python train_equivariance.py --help
```

### Option 2: install the Python dependencies yourself

From the repository root:

```bash
cd evaluation-protocol
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

The current requirements are lightweight except for the deep learning stack:

- `torch`
- `torchvision`
- `timm`
- `hydra-core`
- `omegaconf`
- `loguru`
- `tqdm`
- `numpy`
- `Pillow`
- `matplotlib`
- `wandb` is optional and only needed when `wandb.use=true`

## Dataset

The default dataset config is in `configs/dataset/unreal_motion_capture.yaml`.

It expects the directory layout produced by `unreal-motion-capture`:

```text
<root>/<environment>/<object_name>/<mode_name>/
```

with images, pose JSON files, and a metadata JSON file inside each mode directory.

If needed, override the dataset root at runtime:

```bash
conda run -n dinov3 python train_equivariance.py dataset.root=/path/to/dataset
```

## How To Run

### Train probes

The main training entrypoint is:

```bash
conda run -n dinov3 python train_equivariance.py
```

Useful overrides:

```bash
conda run -n dinov3 python train_equivariance.py \
  experiment_name=my_run \
  dataset.root=/path/to/dataset \
  dataset.image_size=224 \
  training.save_checkpoints=true
```

Important notes:

- `training.save_checkpoints=true` is required if you want to visualize predictions later.
- For CLIP ViT backbones, use a compatible image size such as `224`.
- Results are written to `results/equivariance_<experiment_name>/`.

Training outputs include:

- `object_metrics.csv`
- `mode_summary.csv`
- `run_config.yaml`
- `checkpoint_manifest.json`
- `checkpoints/*.pt` when checkpoint saving is enabled

### Visualize predictions vs ground truth

After training with checkpoints enabled, run:

```bash
conda run -n dinov3 python visualize_equivariance.py \
  result_dir=results/equivariance_my_run
```

This script reloads the saved probes, recomputes predictions for the configured splits, and writes plots to:

```text
results/equivariance_<experiment_name>/visualizations/
```

By default it considers:

- `train`
- `valid`
- `test` if `dataset.test_ratio > 0`

The current visualization behavior is:

- one figure per `(environment, mode, object)`
- ground truth shown once in one color
- predictions for `train`, `valid`, and `test` overlaid in different colors on the same plot

## Feature Extraction

Feature extraction is implemented in `evals/models/backbone.py`.

The backbone is frozen: its weights are not updated during probe training. Each image is passed through a pretrained `timm` model, and the script extracts one feature vector per image.

When `pool: patch` is selected, the backbone returns the full patch-token sequence instead of a single pooled vector. This mode is intended for Efficient Probing.

The backbone config is controlled by files in `configs/backbone/`, for example:

```yaml
name: clip_b16_laion
pool: mean
```

### Backbone name

`name` selects the pretrained model alias. For example, `clip_b16_laion` maps to a CLIP ViT-B/16 variant from `timm`.

### Pool options

The `pool` option determines how token features are returned from the frozen backbone. The code supports:

- `mean`
- `cls`
- `patch`

#### `pool: mean`

`mean` averages the patch tokens to form the final feature vector.

Behavior in code:

- if the model has prefix tokens such as a CLS token, they are excluded from the average
- only patch tokens are averaged

Conceptually, this gives a feature that summarizes the whole image by aggregating information across spatial tokens.

#### `pool: cls`

`cls` uses the first token directly:

```text
tokens[:, 0]
```

For transformer backbones with a CLS token, this means the representation comes from the dedicated classification token instead of averaging patches.

#### `pool: patch`

`patch` returns all patch tokens directly, while excluding prefix tokens such as CLS.

This does not go through the standard MLP regressor. Instead, it is intended to be paired with the Efficient Probing head, which learns how to aggregate patch tokens before regression.

### Mean vs CLS in practice

A practical way to think about them:

- `mean` is often a more spatially averaged representation
- `cls` is often a more compact single-token summary

Which one works better for equivariance is an empirical question, so it is reasonable to try both.

Example overrides:

```bash
conda run -n dinov3 python train_equivariance.py backbone.pool=cls
conda run -n dinov3 python train_equivariance.py backbone.pool=patch probe=efficient_probing
```

## Probe

The regression head is defined in `configs/probe/regressor.yaml` and implemented in `evals/models/probe.py`.

It is a small MLP trained on top of frozen backbone features:

- output dimension `1` for line modes
- output dimension `2` for orbit modes

An Efficient Probing option is also available in `configs/probe/efficient_probing.yaml`.

This probe:

- expects `backbone.pool=patch`
- applies cross-attention over patch tokens using learned queries
- optionally applies `LayerNorm`
- uses a final linear regressor to predict the target

Example:

```bash
conda run -n dinov3 python train_equivariance.py \
  backbone.pool=patch \
  probe=efficient_probing
```

## Testing

A smoke test is provided:

```bash
conda run -n dinov3 python -m unittest discover -s tests -p 'test_smoke.py'
```

This checks:

- imports without mandatory `wandb`
- mode-safe batching
- training with checkpoint saving
- visualization output generation
